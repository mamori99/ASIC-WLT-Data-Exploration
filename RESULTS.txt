=== Investigation: aggfunc='first' in pivot — does it lose information? ===

Question: The CP2 pivot uses aggfunc='first'. If multiple test_result values
exist per (die, test_txt), information is silently dropped. Could aggregating
with mean/std/range add predictive signal?

Findings:
  CP2 rows:              2,475,216
  Unique dies:           51,567
  Unique test_txt:       48
  Expected combos:       51,567 × 48 = 2,475,216
  Rows per (die, test_txt): ALL = 1 (no duplicates)

Conclusion: Every (wafer_id, x_coord, y_coord, test_txt) combination has
exactly one row in the CP2 data. aggfunc='first' is equivalent to any other
aggregation function — no information is lost. No action needed.

=== Investigation: Label noise — hard_bin vs soft_bin mismatches ===

Question: Do any dies have hard_bin=1 but soft_bin≠1 (or vice versa)?
Such mismatches would be ambiguous labels — the current target definition
(part_fail = NOT(hard_bin==1 AND soft_bin==1)) would label them as fails,
but they might be borderline/mislabeled, capping achievable PR-AUC.

Findings (51,567 dies total):

  COLD bins:

    soft_bin values: {1, 110, 317, 1755, 1762, 1765, 1766, 2033}

    hard_bin=1 AND soft_bin=1 (pass):        49,334
    hard_bin≠1 AND soft_bin≠1 (clear fail):   2,233
    hard_bin=1 BUT soft_bin≠1 (ambiguous):        0
    hard_bin≠1 BUT soft_bin=1 (ambiguous):        0
    Missing cold bin data (NaN):                  1

    Fail breakdown by hard_bin:
      hard_bin=20, soft_bin=2033:  1,923 dies (86.1% of cold fails)
      hard_bin=17, soft_bins={1755,1762,1765,1766}: 243 dies (10.9%)
      hard_bin=31, soft_bin=110:     65 dies (2.9%)
      hard_bin=3,  soft_bin=317:      1 die  (0.04%)

  HOT bins:
    hard_bin values: {1, 3, 17, 20, 31}
    soft_bin values: {1, 110, 305, 317, 1755, 1762, 2033}

    hard_bin=1 AND soft_bin=1 (pass):        49,509
    hard_bin≠1 AND soft_bin≠1 (clear fail):   2,058
    hard_bin=1 BUT soft_bin≠1 (ambiguous):        0
    hard_bin≠1 BUT soft_bin=1 (ambiguous):        0
    Missing hot bin data (NaN):                   5

    Fail breakdown by hard_bin:
      hard_bin=20, soft_bin=2033:  1,923 dies (93.4% of hot fails)
      hard_bin=31, soft_bin=110:     63 dies (3.1%)
      hard_bin=17, soft_bins={1755,1762}: 56 dies (2.7%)
      hard_bin=3,  soft_bins={305,317}:   11 dies (0.5%)

  Target summary:
    cold_part_fail: 2,233 fails (4.33%), 0 ambiguous (0.0%)

Conclusion: Zero label noise from hard_bin/soft_bin mismatches. Every fail die
has BOTH hard_bin≠1 AND soft_bin≠1 — the bins are perfectly consistent. The

=== Investigation: Multi-target learning (OOF cross-prediction) ===

Question: cold_part_fail and hot_part_fail are likely correlated. Can we use
one target's out-of-fold prediction as a feature for the other?

Target correlation:
  Pearson: 0.9238
  MCC:     0.9238
  Agreement: 99.39%
  Crosstab: both_pass=49,263 | cold_only=246 | hot_only=71 | both_fail=1,987
  → Extremely correlated. 96.8% of failing dies fail BOTH cold and hot.

Method:
  1. Train independent XGBoost models (saved Optuna params) for each target
  2. Generate leak-free OOF predictions: leave-one-wafer-out within training
     set (3-fold), full-train model for val/holdout
  3. Add other target's OOF probability as a 20th feature
  4. Retrain with same Optuna params, evaluate on holdout

Results:
  Target               Metric     Baseline  Multi-tgt     Delta
  ---------------------------------------------------------------
  hot_part_fail        PR-AUC       0.3655     0.3776   +0.0120
                       Cost           4311       4268       -43
                       FN              415        414        -1
                       FP              161        128       -33
  cold_part_fail       PR-AUC       0.3668     0.3687   +0.0019
                       Cost           4701       4667       -34
                       FN              458        452        -6
                       FP              121        147       +26
  ---------------------------------------------------------------
  TOTAL                Cost           9012       8935       -77

  OOF feature importance: rank #1 in both models (0.100 for hot, 0.090 for cold)

Conclusion: Multi-target OOF gives a modest improvement — total cost drops by
77 (9012→8935), hot PR-AUC gains +0.012. The OOF feature becomes the single
most important feature in both models, confirming the strong cross-target
signal. However, the improvement is small because the targets are already
92.4% correlated — the model can already infer much of this from shared CP2
features. The added complexity (leave-one-wafer-out OOF generation, sequential
training dependency) may not justify the modest gain for production use.
NOT integrated into the main pipeline — marginal benefit vs complexity.

=== Investigation: Neighbor-based spatial features (k=8 nearest dies) ===

Question: Can k-nearest-die spatial features (mean/std of CP2 test values
across neighbors on the same wafer) exploit spatial clustering of failures?

Method:
  1. For each die, find k=8 nearest neighbors using (x_coord, y_coord)
     within the same wafer via cKDTree
  2. Compute mean and std of all 19 surviving features across neighbors
  3. Add 2 aggregate features: nbr_mean_all, nbr_std_all
  4. Apply same |Pearson| > 0.95 correlation pruning
  5. Train with same Optuna-optimized params, evaluate on holdout

  Note: Only CP2 test features are used — no target leakage.

Feature expansion:
  Base features:    19
  + Neighbor raw:   19×2 (mean+std) + 2 (aggregates) = 40
  Total before prune: 59
  After prune:        49 (32 neighbor features survived, 10 pruned)

Results:
  Target               Metric     Baseline  + Neighbor    Delta
  ---------------------------------------------------------------
  hot_part_fail        PR-AUC       0.3655     0.3675   +0.0020
                       Cost           4311       4293       -18
                       FN              415        417        +2
                       FP              161        123       -38
  cold_part_fail       PR-AUC       0.3668     0.3659   -0.0009
                       Cost           4701       4693        -8
                       FN              458        461        +3
                       FP              121         83       -38
  ---------------------------------------------------------------
  TOTAL                Cost           9012       8986       -26

  Top neighbor features by importance:
    nbr_std_y_coord:  0.054 (hot) / 0.059 (cold)
    nbr_std_x_coord:  0.050 (hot) / 0.050 (cold)
    nbr_mean_all:     0.027 (hot) / 0.020 (cold)

Conclusion: Negligible improvement — total cost drops by only 26 (9012→8986),
hot PR-AUC +0.002, cold PR-AUC -0.001. The model feature count grows from
19 to 49 (2.6×) for essentially zero gain. The raw x_coord/y_coord already
capture spatial signal adequately; averaging test values across neighbors adds
minimal new information. NOT integrated — complexity not justified.
